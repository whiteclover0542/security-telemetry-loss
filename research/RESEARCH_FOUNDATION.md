# 연구 기반 — 로그 순서 왜곡과 탐지 회피

- 작성일: 2026-09-11
- 상태: 설계 단계. 핵심 가정 검증 전이며 실험 결과는 없습니다.
- 관심 분야: 정보보안 / 침입 탐지·보안 관제·로그 파이프라인
- 후보 주제 검토와 접은 이유: [주제 선정](../docs/TOPIC_SELECTION.md)

## 문제의식

보안 관제의 탐지 규칙은 압도적으로 시간 윈도우에 의존합니다. "5분 내 인증 실패 10회 후 성공", "1분 내 동일 계정의 다중 지역 접속", "짧은 시간 내 대량 파일 접근"이 전형입니다. 이런 규칙은 이벤트가 **발생한 순서대로 도착한다**는 것을 암묵적으로 전제합니다.

그러나 실제 로그 파이프라인은 그 전제를 보장하지 않습니다. 이벤트는 에이전트 버퍼, 수집기 배칭, 메시지 큐, 재시도와 백프레셔를 거쳐 SIEM에 도달합니다. 각 구간에서 지연이 발생하고, 그 지연은 이벤트마다 다릅니다. 따라서 **도착 순서는 발생 순서와 일치하지 않습니다.**

현장에서 이 현상은 대체로 "약간의 지연"으로 취급되며, 규칙을 작성할 때 고려 대상이 아닙니다.

## 최종 가설

> **공격자가 로그 파이프라인의 특정 구간에 부하를 주어 자신의 행위 이벤트 도착을 지연시키면, 이벤트를 하나도 삭제하지 않고도 시간 윈도우 기반 탐지 규칙의 판정을 회피할 수 있다.**

이 가설이 성립하면 다음이 따라옵니다. 로그는 전부 도착하므로 무결성 검증을 통과하고, 유실이 없으므로 수집량 모니터링에도 걸리지 않습니다. 삭제 흔적도 남지 않습니다. 그럼에도 탐지는 실패합니다.

## 이 가설이 성립하려면 무엇이 참이어야 하는가

가설은 아래 전제들에 의존합니다. **본 설계에 착수하기 전에 데이터로 확인합니다.** 하나라도 무너지면 설계를 수정하거나 주제를 재검토합니다.

| 번호 | 전제 | 확인 방법 | 무너질 경우 |
| --- | --- | --- | --- |
| P1 | 탐지 규칙이 실제로 도착 순서에 의존한다 | 규칙 엔진을 구현해 동일 입력의 순서만 바꿔 판정이 달라지는지 확인 | 가설 무의미. 주제 폐기 |
| P2 | 이벤트에 발생 시각과 도착 시각을 구분할 근거가 있다 | OpTC 이벤트의 timestamp 의미와 정밀도 확인 | 왜곡 모델을 다르게 정의 |
| P3 | 파이프라인 지연이 이벤트마다 다르게 발생할 수 있다 | 버퍼·배칭·재시도 모델링이 현실적인지 문헌과 구현으로 확인 | 왜곡 폭이 작아 공격 성립 불가 |
| P4 | 공격자가 지연을 유도할 수 있는 지점이 존재한다 | 위협 모델에서 공격자 역량을 정의하고 실현 가능성 검토 | 신뢰성 연구로 축소. 보안 기여 약화 |

P1이 가장 중요합니다. 이것이 확인되지 않으면 나머지는 의미가 없으므로 **가장 먼저 측정합니다.**

## 측정 계획

| 항목 | 정의 |
| --- | --- |
| 독립변수 | 파이프라인이 유발하는 도착 순서 왜곡의 정도와 구조 |
| 종속변수 | 시간 윈도우 규칙의 판정 변화. 무왜곡 기준 대비 탐지 실패율 |
| 통제 | 입력 이벤트 집합, 규칙 정의, 윈도우 길이, 임계값을 고정. **이벤트를 삭제하지 않음** |
| 왜곡 모델 | 버퍼 플러시 주기, 배치 크기, 재시도 지연, 홉 수를 매개변수로 하는 도착 시각 변환 |
| 규칙 집합 | 시간 윈도우 의존 유형별로 분류한 탐지 규칙. 각 유형의 취약도를 개별 보고 |
| 공격 모델 | 공격자가 유발 가능한 지연의 상한과 그 비용 |
| 평가 자료 | 확보한 OpTC 호스트 로그와 악성 이벤트 라벨 |

왜곡량을 직접 제어하므로 정답을 확보할 수 있습니다. 어떤 이벤트가 얼마나 늦게 도착했는지 우리가 알고 있으므로, 규칙 판정 변화의 원인을 특정할 수 있습니다.

## 기여 목표

1. **파이프라인 순서 왜곡의 형식화** — 멀티홉 버퍼링·배칭·재시도가 만드는 도착 시각 분포를 매개변수 모델로 정의합니다.
2. **규칙 취약성의 정량화** — 시간 윈도우 규칙이 왜곡 정도에 따라 어떻게 무력화되는지 유형별로 측정합니다.
3. **공격 가능성 분석** — 공격자가 유발할 수 있는 왜곡의 범위와 그에 따른 회피 성공률을 제시합니다.
4. **완화 기법 설계와 평가** — 워터마크 기반 재정렬, 발생 시각 기준 지연 허용 윈도우 등을 설계하고 재정렬 버퍼 크기, 탐지 지연, 회피 저항성, 처리량 오버헤드의 트레이드오프를 측정합니다.

## 반증 조건

- P1이 성립하지 않으면, 즉 순서를 바꿔도 규칙 판정이 변하지 않으면 가설을 지지하지 않습니다.
- 현실적인 파이프라인 매개변수 범위에서 회피 성공률이 무왜곡 대비 유의하게 오르지 않으면 가설을 지지하지 않습니다.
- 공격자가 유발 가능한 지연의 상한이 규칙 윈도우보다 현저히 작으면 공격 시나리오는 성립하지 않으며, 그 경우 신뢰성 문제로만 보고합니다.

어느 경우든 결과를 그대로 보고하며, 결과에 맞추어 가설이나 측정 방식을 바꾸지 않습니다.

## 진행 원칙

이전 주제에서 "탐지기를 실행할 수 있다"는 가정을 검증하지 않은 채 환경 구축에 시간을 쓴 뒤 그 가정이 무너졌습니다. 이번에는 순서를 뒤집습니다.

1. P1을 최소 구현으로 먼저 확인합니다.
2. 확인되면 왜곡 모델과 규칙 집합을 고정합니다.
3. 고정한 뒤에 측정에 들어갑니다.
4. 모든 고정 사항은 결과를 보기 전에 기록합니다.
