# 카드 3 — 탐지기 선택 기록

- 결정일: 2026-09-10
- 상태: 구현과 입력을 고정했으며 기준 실행 전

## 결정

주 탐지기는 PIDSMaker의 KAIROS 구현을 commit `ae1e9fd42604c769c01b2eaed6fb7f65e27f3cac`으로 고정한다. 각 OpTC 공격 호스트에 공개된 튜닝 인자를 적용하고, `node_evaluation`과 `max_val_loss`를 사용한다. 모델은 2019-09-19~21 정상 자료로 학습하고, 2019-09-22 정상 자료로 임계값을 산출한다. 산출된 체크포인트, 임계값, 초기 추론 상태를 고정한 뒤 무유실 기준과 모든 유실 변형을 재생한다.

기준 실행에서 SysClient0201, SysClient0501, SysClient0051의 수정 정답 노드가 각각 하나도 탐지되지 않으면 본 유실 비교를 시작하지 않는다. 결과를 본 뒤 모델이나 임계값을 바꾸면 고정 탐지기 비교가 아니기 때문이다.

## 확인한 후보와 선택 이유

| 후보 | 확인 결과 | 판단 |
| --- | --- | --- |
| Inria OpTC KAIROS 노트북 | OpTC용 전처리·학습 예시는 있으나 평가 시간창마다 `평균 + 2.5 × 표준편차`를 다시 계산한다. 그래프 학습 노트북 파일은 JSON 제어문자 오류도 있어 그대로 자동 실행하기 어렵다. | 테스트 입력 삭제에 따라 임계값이 변하므로 주실험에서 제외한다. 참고 구현으로만 보존한다. |
| PIDSMaker KAIROS | 별도 검증 자료에서 `max_val_loss` 임계값을 계산하고 OpTC 세 호스트 설정과 튜닝 명령을 제공한다. 평가 코드는 검증 경로에서 임계값을 얻고 테스트 점수에 적용한다. | 고정 임계값 실험에 맞아 주 탐지기로 선택한다. |

고정 커밋을 실제로 확보해 위 판단의 근거를 코드에서 확인했다. `pidsmaker/detection/evaluation_methods/node_evaluation.py`의 `get_node_predictions`는 `threshold_method`가 `magic`일 때만 테스트 경로에서 임계값을 얻고, 그 외에는 검증 경로에서 얻는다. 우리가 사용하는 `max_val_loss`는 후자에 해당하므로 테스트 입력의 유실이 임계값을 바꾸지 않는다. 같은 함수가 노드별 이상 점수와 정답 여부를 함께 돌려주므로, 사례 탐지와 라벨 노드 재현율을 같은 출력에서 계산할 수 있다.
| PIDSMaker KAIROS 큐 평가 | 설정 스키마가 이 경로를 “고장 나 있어 갱신 필요”라고 명시한다. 기본 KAIROS 설정도 `node_evaluation`을 사용한다. | 주평가에서 제외한다. |

## 고정 판정

- 사례 정답은 완전한 무유실 입력에서 만든 수정 라벨과 그 SHA-256을 사용한다.
- 사례 탐지는 해당 사례의 고정 정답 노드 중 하나 이상이 고정 임계값을 엄격히 초과했는지로 판정한다.
- 고정 정답 노드 중 임계값을 초과한 비율(라벨 노드 재현율)을 모든 실행에서 함께 기록한다. 사례 탐지 판정이 포화될 때 결론의 근거가 되는 공동 1차 지표이며, 분모는 무유실 입력에서 고정한 정답 노드 수다.
- 유실 입력에서 사라진 정답 노드는 미탐지로 남으며 사례 분모에서 제거하지 않는다.
- 모델 재학습, 테스트별 임계값 재산출, 테스트별 초기 상태 승계는 금지한다.
- PIDSMaker의 공격 탐지 비율과 노드 수준 정밀도는 보조 지표로 함께 보존한다.

호스트별로 데이터셋과 튜닝 인자가 분리되어 있으므로 SysClient0201·0501·0051에 각각 하나씩, 총 3개의 학습 체크포인트와 3개의 검증 임계값을 산출한다. "고정"은 한 사례 안에서 무유실 기준과 모든 유실 변형이 같은 체크포인트와 같은 임계값을 쓴다는 뜻이며, 세 사례가 하나의 값을 공유한다는 뜻이 아니다. 사례 간 탐지율을 비교할 때 이 점을 함께 밝힌다.

## 실행 가능성 및 남은 관문

Windows 호스트를 재조회한 결과 메모리 31.9GiB, 여유 디스크 1,882GiB, PostgreSQL 18.3, GeForce RTX 3080(VRAM 10,240MiB)을 사용할 수 있다. 이전 기록의 "PostgreSQL·NVIDIA 미구성"은 WSL 쪽 조회 결과였다. 남은 실행 관문은 VRAM 10GB가 호스트별 6.7~9GB 전처리 자료를 다루기에 충분한지, 그리고 Docker 엔진 연결이다. 어느 쪽도 아직 확인하지 않았다.

학습 2019-09-19~21 및 검증 2019-09-22 TAR의 파일 ID·크기·MD5는 고정했다. 정상 호스트 파일 12개 중 SysClient0201의 09-19·09-20 2개를 확보해 검증했고, 나머지 10개와 세 공격 호스트 로그는 Inria 서버가 HTTP 503을 반환하여 아직 받지 못했다. 다음 관문은 남은 입력을 확보하고 무유실 기준 실행을 통과하는 것이다.

검토 근거는 [고정 입력 설정](../config/study_inputs.json), [수정 코드 출처 manifest](correction_sources_manifest.json), 제외된 외부 코드 `external/PIDSMaker`와 `external/corrected-optc-review`에 있다. 외부 코드 자체는 저장소에 포함하지 않는다.
