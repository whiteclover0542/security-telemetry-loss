- 연구 내용 문서: [연구 기반](../research/RESEARCH_FOUNDATION.md) · [주제 선정과 접은 후보](TOPIC_SELECTION.md)

## 주제 전환 기록

2026-09-11에 주제를 전환했습니다. 이전 주제(유실의 시간적 구조가 공격 탐지에 미치는 영향)는 데이터 확보와 환경 구축, 예비 측정까지 수행한 뒤 접었습니다. 접은 이유는 두 가지이며 모두 실측에 근거합니다.

1. 탐지기 재생이 이 하드웨어에서 불가능함을 4 에폭까지 실제로 돌려 확인했습니다. 설계상 723회 실행은 약 105일, 최대 축소한 63회도 약 9일이며 메모리 한계로 완주하지 못했습니다.
2. 탐지기 없이 증거 소실만 측정하는 대안으로 결과를 얻었으나, 그 결과가 계산으로 예측 가능한 수준이라 새로 알려주는 바가 부족했습니다.

전환 판단과 검토한 다른 후보는 [주제 선정](TOPIC_SELECTION.md)에 있습니다. 이전 작업 일체는 [preliminary/](../preliminary/)에 보존했습니다. 확보한 데이터와 실행 환경, 검증 도구는 새 주제에서 그대로 사용합니다.

## 해야 할 일

- [x] **P1 확인 완료**: 실제 OpTC 로그(413,207건)에서 이벤트를 삭제하지 않고 순서만 바꿔 경보가 최대 38% 감소함을 확인했습니다. 최적 지연이 큰 값이 아니라 규칙 윈도우 크기 근처라는 예상 밖 관찰도 얻었습니다.
- [x] **P2 확인 완료**: OpTC의 timestamp가 발생 시각 하나뿐이고(수집·도착 시각 없음), 원본이 완전히 시간순이며 밀리초 정밀도임을 확인했습니다. 원본 로그를 지연 없는 이상적 발생 순서 스트림으로 쓸 근거입니다.
- [x] **규칙 카탈로그 고정**: OpTC로 표현 가능한 규칙 5종(net_scan·mass_file·remote_thread·module_load·beacon)을 조사·캘리브레이션해 임계값과 함께 사전 등록했습니다.
- [ ] P1 일반화 스윕: 규칙 5종 × 사례 3개 × 지연 비율·크기·구조 × 시드로 "작은 지연이 최악"과 표적 지연 효율을 확인합니다.
- [ ] P3~P4 전제를 확인합니다.
- [ ] 파이프라인 순서 왜곡 모델을 형식화하고 매개변수를 고정합니다.
- [ ] 탐지 규칙 집합을 유형별로 정의하고 고정합니다.
- [ ] 위협 모델과 공격자 역량을 정의합니다.
- [ ] 규칙 취약성을 정량화합니다.
- [ ] 완화 기법을 설계하고 트레이드오프를 측정합니다.
- [ ] 결과 해석, 논문 작성, 재현 패키지 검증을 진행합니다.
