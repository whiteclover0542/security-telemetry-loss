- 작성일: 2026-09-10

## 연구 주제와 최종 가설

- 관심 분야: 정보보안 / 침입 탐지·디지털 포렌식·운영체제 관측
- 연구 주제: 보안 이벤트 유실의 구조가 공격 탐지와 원인 추적에 미치는 영향 및 탐지 상태 복구
- 최종 가설 A-v1: **OpTC의 공격별 평가 구간을 고정된 탐지기로 재생할 때, 추가 유실률과 제거 이벤트 수가 같다면 시간적으로 연속된 유실은 균등 무작위 유실보다 무유실 기준 대비 공격 사례 탐지율을 더 크게 낮춘다.**

독립변수는 유실의 시간적 구조이고 종속변수는 무유실 기준 대비 공격 사례 탐지율 감소입니다. 탐지기·전처리·평가 구간·삭제 개수는 고정합니다. 유실 위치는 공격 라벨을 보지 않고 시드로 정하며, 정답은 평가에만 사용합니다.

반증 기준은 사전 평가 범위에서 연속 유실의 탐지율 감소가 무작위 유실보다 크지 않거나, 두 방식의 차이가 사전에 정한 실질적 동등 범위 안에 들어오는 경우입니다. 신뢰구간과 동등 범위는 실제 독립 공격 사례 수를 확인한 뒤 결과를 보기 전에 고정합니다.

## 후보 비교와 선택 이유

| 후보 | 한 문장 가설 | 이번 선택 |
| --- | --- | --- |
| A — 유실의 시간적 구조 | 연속 유실은 무작위 유실보다 공격 사례 탐지율을 더 낮춘다. | 선택. 동일 로그·동일 탐지기에서 직접 비교할 수 있습니다. |
| B — 이벤트 종류별 중요도 | 프로세스 생성 이벤트 유실은 파일·네트워크 이벤트 유실보다 탐지율을 더 낮춘다. | 제외. 이벤트 빈도와 탐지기 의존성을 별도로 통제해야 합니다. |
| C — 탐지 상태 복구 | 상태 스냅샷 반영은 단순 수집 재개보다 탐지율을 높인다. | 제외. 독립 스냅샷과 상태 정의가 필요합니다. |
| D — 관측 부족 표시 | 규칙별 관측 부족 표시는 전체 유실률 경고보다 미탐지를 잘 구별한다. | 제외. 실제 운영 환경에서 보이는 유실 신호와 정답이 필요합니다. |

## 측정과 범위

| 항목 | 정의 |
| --- | --- |
| 실험 단위 | 공격 라벨을 확인할 수 있는 호스트·시간 구간 |
| 추가 유실률 | 삭제 이벤트 수 / 선택 원본 구간 이벤트 수 |
| 무작위 유실 | N개 이벤트 중 k개를 비복원 균등 추출해 제거 |
| 연속 유실 | 시간순 이벤트에서 연속 k개를 제거 |
| 1차 지표 | 무유실 기준 대비 공격 사례 탐지율 감소 |
| 보조 지표 | 정상 구간 시간당 오탐, 삭제 구간 길이·공격 구간 겹침, 가능하면 추적 성능 |
| 데이터 범위 | OpTC evaluation 구간의 공격 호스트·시간 구간과 benign 구간 |

이번 연구는 로그 재생 중 추가한 유실의 영향을 측정합니다. 실제 센서 부하가 만드는 유실률이나 유실 구조를 일반화하지 않습니다.

## 판단 기록

- 사용자 판단: 보안 이벤트 유실의 구조, 공격 탐지·원인 추적 영향, 탐지 상태 복구를 연구 주제로 정했습니다.
- AI 작업: 질문 10개와 후보 가설 4개를 만들고, 측정 가능성·필요 증거·선행 연구 범위를 비교했습니다.
- 가설 구체화: 넓은 연구 방향에서 동일 유실률, 동일 삭제 수, 동일 탐지기, 공격 사례 탐지율 감소, 반증 기준까지 순서대로 고정했습니다.
- 후속 판단: 실제 로그와 독립 공격 사례 수를 확인한 뒤 통계 절차와 실질적 동등 범위를 결과 확인 전에 정합니다.
