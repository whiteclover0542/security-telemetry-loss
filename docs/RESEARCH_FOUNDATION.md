# 연구 기반 — 질문, 가설, 측정 계획

- 작성일: 2026-09-10
- 상태: 카드 1 완료. 실제 실험 결과는 아직 없습니다.

## 연구 주제와 최종 가설

- 관심 분야: 정보보안 / 침입 탐지·디지털 포렌식·운영체제 관측
- 연구 주제: 보안 이벤트 유실의 구조가 공격 탐지와 원인 추적에 미치는 영향 및 탐지 상태 복구
- 최종 가설 A-v2: **OpTC의 공격별 평가 구간을 고정된 탐지기로 재생할 때, 추가 유실률과 제거 이벤트 수가 같다면 시간적으로 연속된 유실은 균등 무작위 유실보다 탐지 결과의 시드 간 변동을 크게 만든다. 즉 연속 유실의 피해는 평균적으로 더 큰 것이 아니라 더 예측하기 어렵다.**

## 가설 수정 기록 — A-v1에서 A-v2로

수정일 2026-09-10. 실험 결과를 보기 전이며 어떤 조건의 탐지 결과도 존재하지 않습니다.

- **수정 전 A-v1**: 같은 추가 유실률과 제거 이벤트 수에서 연속 유실은 균등 무작위 유실보다 무유실 기준 대비 공격 사례 **탐지율을 더 크게 낮춘다**.
- **수정 후 A-v2**: 같은 조건에서 연속 유실은 균등 무작위 유실보다 탐지 결과의 **시드 간 변동을 크게 만든다**.

수정 이유는 세 가지입니다.

1. **측정된 사실**: 확보한 로그에서 평가 구간을 산출해 보니 122분 창에 10% 연속 유실을 적용하면 삭제 구간의 실제 길이가 564.6초, 약 9.4분입니다. 창의 약 92%는 손상되지 않습니다. 연속 유실은 평균적으로 증거를 더 많이 지우는 것이 아니라, 결정적 단계에 떨어지면 치명적이고 아니면 거의 무해한 복불복에 가깝습니다.
2. **기존 증거와의 정합**: [3]은 시스템 호출 하나가 빠지면 손상된 실행이 정상 실행과 같아 보일 수 있다고 보고합니다. 이는 **어느 레코드가 사라지느냐가 결과를 가른다**는 뜻이며, 평균 차이보다 변동 차이를 직접 지지합니다. A-v1의 방향은 확인한 문헌 어디에서도 지지되지 않았습니다.
3. **표본 구조와의 정합**: 유실 시드 30개는 서로 독립적인 공격이 아니므로 평균 비교에서는 계속 한계로 남습니다. 변동을 종속변수로 두면 같은 시드 30개가 한계가 아니라 측정 수단이 됩니다.

A-v1의 평균 비교는 폐기하지 않고 함께 사전 등록해 결과를 모두 보고합니다. 두 가설은 같은 실행 자료로 계산하며 추가 실행이 필요하지 않습니다.

## 연구 질문 10개

관심 분야는 정보보안 중 침입 탐지·디지털 포렌식·운영체제 관측입니다. 사용자가 확정한 전체 연구 방향은 유지하고, 먼저 검증할 주가설을 골랐습니다. 아래 수집 가능성은 자료 구조에 근거한 계획이며, 실제 다운로드·파싱·실험 성공을 뜻하지 않습니다.

1. **Q01 — 같은 유실률에서 무작위 유실과 연속 유실의 공격 탐지율은 다른가?**
   - 방법: 같은 원본 로그에 같은 개수의 서로 다른 유실 마스크를 적용하고 동일 탐지기로 재생합니다.
   - 처리: 주가설 후보 A입니다.
2. **Q02 — 탐지가 유지되더라도 공격 시작점까지의 추적 경로는 끊어질 수 있는가?**
   - 방법: 고정된 조사 시작점에서 역추적한 경로와 원본 기준 경로·공격 정답을 비교합니다.
   - 처리: A의 보조 분석입니다.
3. **Q03 — 프로세스 생성·파일·네트워크 이벤트 중 어떤 유실 영향이 큰가?**
   - 방법: 이벤트 종류와 개수를 통제한 유실 마스크와 각 종류를 사용하는 탐지 규칙을 비교합니다.
   - 처리: 후보 B입니다.
4. **Q04 — 유실이 공격 전·중·후 어디에 놓이는지에 따라 피해가 다른가?**
   - 방법: 공격 시점 라벨과 유실 구간의 겹침 정도를 분석합니다.
   - 처리: A의 보조 분석입니다.
5. **Q05 — 수집 정상화 뒤에도 이전 유실의 탐지 상태 차이가 남는가?**
   - 방법: 정상화 시점 이후 같은 이벤트를 입력하면서 기준 탐지기의 상태·출력을 비교합니다.
   - 처리: 후보 C입니다.
6. **Q06 — 상태 초기화와 상태 스냅샷 반영의 복구 효과가 다른가?**
   - 방법: 시점별 실제 상태 스냅샷, 재시작·보정 기능, 복구 뒤 평가 사건이 필요합니다.
   - 처리: C의 확장입니다. 추가 자료가 필요합니다.
7. **Q07 — 상태를 복구해도 이미 사라진 과거 공격 경로는 복구할 수 없는가?**
   - 방법: 현재 상태와 과거 사건 이력을 따로 보관한 검증 자료가 필요합니다.
   - 처리: C의 확장입니다. 스냅샷과 과거 증거를 구분해야 합니다.
8. **Q08 — 규칙별 관측 부족 표시는 유실 미탐지를 사전에 구별하는가?**
   - 방법: 탐지 규칙의 필요 이벤트 정의, 실제로 관측 가능한 유실 신호, 기준 실행 결과가 필요합니다.
   - 처리: 후보 D입니다.
9. **Q09 — 탐지 시간창 길이가 유실 영향과 정상화 뒤 회복에 영향을 주는가?**
   - 방법: 시간창을 고정한 실험군별 로그 재생과 탐지 시점을 비교합니다.
   - 처리: A·C 후속 분석이며 주실험과 분리합니다.
10. **Q10 — 실제 수집기 부하의 유실 구조는 인위적 유실과 닮았는가?**
    - 방법: 실제 수집기, 부하 발생기, 독립적인 발생 이벤트 카운터가 필요합니다.
    - 처리: 별도 실측이 필요하며 현재 데이터만으로 답하지 않습니다.

Q01~Q05·Q09는 로그와 공격 라벨을 확보하면 재생 실험으로 접근할 수 있습니다. Q06~Q08·Q10은 별도 상태·유실 신호·실측 장치의 확보 여부를 먼저 확인해야 합니다. 이 구분은 과제 시간을 맞추기 위한 축소가 아니라, 필요한 증거의 차이에 따른 작업 순서입니다.

## 후보 가설 비교와 제외 이유

아래 선택은 사용자가 확정한 연구 주제를 바탕으로 AI가 측정 가능성과 선행 연구를 대조해 제안한 연구 순서입니다. 사용자의 원래 판단과 AI의 세부 가설 선택은 아래 판단 기록에서 구분합니다.

| 후보 | 한 문장 가설 | 장점 | 이번 주가설 선택 및 이유 |
| --- | --- | --- | --- |
| A — 유실의 시간적 구조 | 같은 원본 로그·탐지기·전체 유실률에서 연속 유실은 균등 무작위 유실보다 공격 사례 탐지율을 더 크게 낮춘다. | 원본과 탐지기를 고정한 비교가 가능하고, 원인 추적 저하도 함께 관찰할 수 있다. | 최종 선택. 전체 연구의 출발점인 “유실률만으로 영향을 설명할 수 있는가”를 직접 검증하며, 공개 로그 재생만으로 조작·측정할 수 있다. |
| B — 이벤트 종류별 중요도 | 같은 수의 이벤트를 잃을 때 프로세스 생성 이벤트에 집중된 유실은 파일 또는 네트워크 이벤트에 집중된 유실보다 공격 탐지 재현율을 더 낮춘다. | 어떤 관측을 보호해야 하는지 구체적으로 설명할 수 있다. | 주가설에서 제외. 이벤트 종류별 원래 빈도와 탐지 규칙의 의존성이 효과와 섞이므로 별도 통제가 필요하다. 후속 실험 후보로 보존한다. |
| C — 탐지 상태 복구 | 이벤트 수집 정상화 시점의 상태 스냅샷을 반영하면 단순 수집 재개보다 정상화 이후 공격 탐지 재현율이 높아진다. | 수집 정상화와 탐지 상태 회복의 차이를 다룬다. | 주가설에서 제외. 로그 외의 독립적인 스냅샷과 탐지 상태 정의가 필요하며, 현재 확보 여부가 확인되지 않았다. 전체 연구의 복구 방향으로 보존한다. |
| D — 관측 부족 표시 | 규칙별 관측 부족 표시는 전체 유실률만 사용하는 경고보다 유실로 발생한 미탐지를 더 정확하게 구별한다. | 탐지 결과를 신뢰할 수 있는 조건을 운영자에게 알릴 수 있다. | 주가설에서 제외. 배포 시 실제로 볼 수 있는 유실 신호와 정답 정의가 먼저 필요하다. 실험자가 아는 삭제 목록을 탐지기에 주면 정보 누출이 생긴다. |

## 가설과 반증 기준

독립변수는 유실의 시간적 구조이고 종속변수는 무유실 기준 대비 공격 사례 탐지율 감소입니다. 같은 공격별 평가 구간 안에서 실제 제거 이벤트 수를 일치시키며, 탐지기·전처리·평가 단위는 고정합니다. 연속 유실의 시작점과 무작위 유실 표본은 공격 라벨을 참조하지 않고 시드로 정합니다. 집중 유실이 공격 증거를 비껴가거나 무작위 유실이 여러 필수 증거를 흩어 지울 가능성도 원자료에 그대로 남깁니다.

- A-v2 반증 결과: 사전에 정한 평가 범위에서 연속 유실의 시드 간 표준편차가 균등 무작위 유실보다 크지 않으면 A-v2를 지지하지 않습니다. 심각 저하 시드 비율에서도 연속 유실이 더 높지 않으면 같은 판단을 강화합니다.
- A-v1 반증 결과: 연속 유실의 탐지율 감소가 균등 무작위 유실보다 크지 않거나 두 방식의 차이가 실질적 동등 범위 안에 있으면 A-v1을 지지하지 않습니다. 측정된 삭제 구간 길이(122분 중 9.4분)를 고려하면 이 결과가 나올 가능성이 높다고 결과 확인 전에 예상합니다.
- 지표별 예상 방향을 결과 확인 전에 나눠 적습니다. 사례 탐지율과 라벨 노드 재현율의 **평균**에서는 차이가 없거나 연속 유실이 오히려 덜 해로울 수 있습니다. 연속 유실이 평가 구간의 약 8%만 제거하고 나머지 시간의 증거를 온전히 남기기 때문입니다. **변동**과 경로 보존율에서는 연속 유실이 더 해로울 것으로 예상합니다. 끊긴 구간은 되짚어 갈 수 없기 때문입니다.
- 판단 방식 초안: 차이의 추정값과 신뢰구간을 함께 보고, 신뢰구간 전체가 동등 범위 안이면 실질적 차이 없음, 전체가 동등 범위 밖 한쪽에 있으면 차이를 지지, 나머지는 판단 유보로 구분합니다.
- 실질적 동등 범위와 신뢰구간 계산법은 데이터의 독립적인 공격 사례 수를 확인한 뒤 결과를 보기 전에 고정합니다. 현재 수치를 임의로 확정하지 않습니다.
- 유의하지 않다는 이유만으로 “차이가 없다”고 결론 내리지 않습니다. 유실 난수만 바꾼 반복은 서로 다른 공격 사례 수를 늘리지 않습니다.

## 측정 방법과 수집 범위

| 항목 | 정의 및 계획 |
| --- | --- |
| 실험 단위 | 공격 라벨을 확인할 수 있는 호스트·시간 구간. 구간과 탐지 성공 판정 규칙은 결과 확인 전에 고정한다. |
| 추가 유실률 | 삭제 이벤트 수 / 선정한 원본 구간 이벤트 수. 원본 자체가 완전하게 수집되었다는 의미가 아니다. |
| 무작위 유실 | 원본 이벤트 N개에서 k개를 비복원 균등 추출해 제거한다. 실제 제거 수를 집중 유실과 일치시킨다. |
| 집중 유실 | 시간순으로 정렬한 이벤트에서 연속 k개를 제거한다. 시작 위치는 공격 라벨을 보지 않고 정한다. 실제 시간 길이와 공격 구간 겹침은 별도 기록한다. |
| 독립변수 | 주비교는 유실의 시간적 구조. 유실률별로 비교하며 주비교 유실률은 실험 전에 하나를 지정한다. |
| 고정 조건 | 원본 로그, 전처리, 탐지 규칙·모델·임계값, 초기 상태, 평가 구간, 삭제 이벤트 수. 테스트 유실 결과에 맞춘 재학습이나 임계값 조정은 하지 않는다. |
| 1차 지표 | 공격 사례 탐지율 = 탐지된 정답 공격 사례 수 / 평가 가능한 정답 공격 사례 수. 주효과는 각 유실 방식의 무유실 기준 대비 탐지율 감소와 두 감소량의 차이다. |
| 오탐 확인 | 정상 구간의 경보 수와 평가 시간을 함께 기록해 시간당 오탐을 계산한다. 경보를 늘린 것만으로 탐지가 좋아졌다고 해석하지 않는다. |
| 원인 추적 보조 지표 | 독립적인 공격 경로 정답이 있으면 경로의 노드·간선 정밀도와 재현율을 평가한다. 없으면 원본 로그 기준 경로의 보존율만 보고하고 이를 실제 공격 복원 정확도라고 부르지 않는다. |
| 조사 시작점 | 추적 성능만 비교할 때는 유실 방식과 무관한 같은 시작점을 사용한다. 탐지부터 추적까지의 전체 평가에서는 탐지 실패도 결과에 포함한다. |
| 유실률·반복 | 추가 유실 0%를 기준으로 1%·5%·10%·20%를 사용한다. 유실 조건별 난수 시드 30개를 적용한다. 이는 표본 확보 실적이 아니다. |
| 데이터 범위 | OpTC evaluation 구간에서 제공자 레드팀 정답과 원본 호스트 로그를 대응시킬 수 있는 공격별 호스트·시간 구간을 후보로 삼는다. 무유실 기준 탐지 성공 사례를 1차 유실 영향 분석 대상으로 하고, 전체 라벨 공격 결과도 별도로 보고한다. benign 구간은 오탐 기준선에 사용한다. |
| 수집 완료 조건 | 대상 로그 파일, 체크섬, 출처·다운로드 날짜, 정답 라벨, 전처리 및 제외 기록 확보. 전체 데이터를 받았다고 가정하지 않는다. |
| 실행 전 확인 | 작은 로그 표본의 접근·파싱, 공격 라벨 대응, 유실 없는 기준 탐지, 정상 구간 오탐을 점검한다. 결과가 마음에 들지 않는다는 이유로 사례를 제외하지 않는다. |
| 적용 한계 | 로그 재생에서 추가한 유실의 영향을 평가한다. 실제 센서가 어떤 부하에서 얼마나 유실하는지는 Q10의 별도 실험 없이는 주장하지 않는다. |

현재까지의 판단은 로그 완전성이 provenance 분석에 중요하며 특정 레코드 누락이 거짓 음성과 경로 단절을 만들 수 있다는 것입니다. 확인한 범위에서는 같은 추가 유실률·제거 개수에서 연속 유실과 균등 무작위 유실이 공격 탐지 결과에 주는 영향을 직접 비교한 결과를 찾지 못했으며, 그 영향의 변동을 다룬 결과도 찾지 못했습니다. 이는 체계적 문헌고찰이나 절대적 최초성 주장이 아닙니다.

## AI와 사용자의 판단 기록

- 사용자 판단: 보안 이벤트 유실의 구조, 공격 탐지·원인 추적 영향, 탐지 상태 복구를 연구 주제로 확정했습니다. 이는 기존 진행 기록에서 이어받은 내용입니다.
- 이번 AI 작업: 연구 질문 10개를 생성하고, 필요한 증거에 따라 후보 4개를 비교했습니다. 출처의 데이터 구조와 알려진 문제를 확인하고, 측정 가능성과 기존 연구의 범위를 근거로 A-v1을 검증 가설로 제안했습니다.
- 가설을 다듬은 과정: 넓은 연구 질문 → 동일 유실률 비교 → 동일 삭제 개수·동일 탐지기 통제 → 공격별 평가 구간 명시 → 무유실 대비 탐지율 감소를 종속변수로 지정 → 가설 A-v1 → 삭제 구간 길이 실측 후 종속변수를 변동으로 바꾼 A-v2.
- A-v2로의 수정에서 AI가 한 일: 구현을 검토해 유실 범위가 평가 구간이 아니라 하루 전체에 걸려 있음을 발견하고 고쳤습니다. 고친 도구로 실제 로그에서 삭제 구간 길이를 측정했고, 그 값(122분 중 9.4분)이 A-v1의 방향 예측과 맞지 않는다는 점과 인용 문헌 [3]이 평균보다 변동을 지지한다는 점을 근거로 A-v2를 제안했습니다.
- 사용자 판단: A-v2로의 전환을 승인했습니다. 난이도가 높은 주제를 유지하기로 한 결정도 사용자의 것입니다.
- 남은 판단: 데이터 파일·공격 구간·통계 절차·실질적 동등 범위는 결과를 보기 전에 고정합니다. 실험 결과는 아직 없습니다.
